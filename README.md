# 회의록 전자서명 시스템

인사자문위원회 같은 회의를 마친 뒤 회의록을 온라인으로 확인·서명받고 PDF로 출력하는 도구입니다.
구글 시트 + Google Apps Script로 동작하므로 별도 서버나 비용이 들지 않습니다.

## 이렇게 동작합니다

1. **관리자**가 회의록(일시·장소·위원·안건·회의 결과·확인 날짜)과 위원 명단(구분·직위·성명)을 입력합니다.
2. 저장하면 위원마다 **6자리 접속 비밀번호**와 **전용 링크**가 만들어집니다. `안내문 복사`로 메신저 등으로 보내세요.
3. **위원**은 링크로 접속해 비밀번호를 입력하고, 회의록을 확인한 뒤 서명(손으로 쓰거나 `이름으로 서명`)하고 **동의**를 누릅니다.
4. 관리자 화면에서 서명 현황을 보고, 다 모이면 **PDF 출력**을 누릅니다.
   - `인쇄 / PDF로 저장`: 인쇄 창에서 대상(프린터)을 'PDF로 저장'으로 고릅니다. 양식이 가장 정확합니다.
   - `구글 드라이브에 저장`: 드라이브의 '회의록 전자서명 PDF' 폴더에 바로 저장합니다.
   - 2쪽부터 **전자서명 확인 내역(감사추적)**이 들어갑니다. 위원별 열람·서명 일시, 기기, 문서 확인값, 전체 처리 이력이 담깁니다.
   - 모든 위원이 서명하면 **자동으로 마감**됩니다.

### 안전장치
- 비밀번호는 암호화(해시)해서 저장하며, 발급 직후에만 볼 수 있습니다. 잊으면 `비밀번호 재발급`.
- 비밀번호를 5번 틀리면 잠깁니다(재발급하면 풀림).
- 서명 후 관리자가 내용을 고치면 위원들이 다른 내용에 서명한 셈이 되므로, 경고 후 **서명이 모두 초기화**됩니다.
- `서명 마감`을 누르면 더 이상 서명할 수 없습니다.
- 모든 접속·서명 기록은 시트의 `Log` 탭에 남습니다.

## 설치 방법 (처음 한 번, 약 10분)

1. [구글 시트](https://sheets.new)를 새로 만듭니다. 이름은 예: `회의록 전자서명 데이터`.
2. 메뉴 **확장 프로그램 → Apps Script**를 엽니다.
3. 왼쪽의 `Code.gs` 내용을 모두 지우고, 이 저장소의 [`src/Code.gs`](src/Code.gs) 내용을 붙여넣습니다.
4. 파일 옆 **＋ → HTML**을 눌러 이름을 `Index`로 만들고(확장자 없이), [`src/Index.html`](src/Index.html) 내용을 붙여넣습니다.
5. 왼쪽 **⚙ 프로젝트 설정**에서 시간대를 `(GMT+09:00) 서울`로 맞춥니다.
6. 오른쪽 위 **배포 → 새 배포** → 유형 **웹 앱**:
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
7. **배포**를 누르고 권한을 승인합니다. "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (프로젝트 이름)(으)로 이동**을 누르세요. 본인이 만든 스크립트라서 나오는 안내입니다.
8. 나온 **웹 앱 URL** 끝에 `?page=admin`을 붙여 접속합니다. 처음 접속하면 관리자 비밀번호를 정하게 됩니다.
   - 예: `https://script.google.com/macros/s/……/exec?page=admin`
   - 이 주소를 즐겨찾기 해 두세요.

> **학교 구글 계정(Google Workspace)을 쓰는 경우**: 관리자 정책에 따라 6번에서 '모든 사용자'가 없고 '○○학교 내 사용자'만 보일 수 있습니다.
> 그러면 위원도 학교 구글 계정으로 로그인해야 접속됩니다. 위원이 계정 없이 접속하게 하려면 개인 구글 계정으로 설치하세요.

### 바로가기 주소

- PDF 위변조 확인: https://gyo6star8i.github.io/sign/verify

(웹 앱을 **새 배포**로 다시 만들어 주소가 바뀌면 `index.html`, `admin/index.html`, `verify/index.html`의 주소도 바꿔야 합니다.)

### 관리자 비밀번호
- **바꾸기**: 관리자 화면 오른쪽 위 **비밀번호 변경**.
- **잊어버렸을 때(초기화)**: Apps Script → **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성**에서 `ADMIN_PW_HASH`, `ADMIN_PW_SALT` 두 줄을 삭제하고 저장합니다.
  다음에 관리자 페이지에 들어가면 비밀번호를 새로 만드는 화면이 나옵니다. 회의록과 서명 기록은 그대로 남습니다.

### 코드를 업데이트할 때
Apps Script에서 파일 내용을 바꾼 뒤 **배포 → 배포 관리 → ✏ 수정 → 버전: 새 버전 → 배포**를 눌러야 반영됩니다. (주소는 그대로 유지됩니다.)

## 다른 선생님께 나눠 드리기

데이터(회의록·비밀번호·서명)는 설치한 사람의 구글 시트에 저장되므로, **학교(사용자)마다 각자 설치**합니다.
다른 학교 설치본에서는 위원 링크가 자동으로 긴 웹 앱 주소로 만들어집니다(짧은 링크는 이 저장소 주인의 웹 앱 전용).

### 방법 1. 사본 만들기 링크로 나눠 주기 (권장)
**나눠 주는 사람(처음 한 번)**
1. 데이터가 없는 **새 구글 시트**를 만들고 이름을 `회의록 전자서명 (배포용)`으로 정합니다. ※ 실제로 쓰는 시트를 나눠 주면 회의록 내용까지 복사되니 꼭 새 시트로 만드세요.
2. **확장 프로그램 → Apps Script**에서 `Code.gs`, `Index.html`을 붙여넣고 저장합니다(배포는 하지 않아도 됩니다).
3. 시트 오른쪽 위 **공유 → 일반 액세스: 링크가 있는 모든 사용자(뷰어)** 로 바꾸고 링크를 복사합니다.
4. 링크 끝의 `/edit…` 부분을 `/copy`로 바꿉니다.
   예: `https://docs.google.com/spreadsheets/d/시트ID/copy`

**받는 사람**
1. 받은 `/copy` 링크를 열고 **사본 만들기**를 누릅니다(코드까지 함께 복사됩니다).
2. 복사된 시트에서 **확장 프로그램 → Apps Script**를 엽니다.
3. 위 [설치 방법](#설치-방법-처음-한-번-약-10분)의 **5번(시간대)부터** 그대로 진행합니다.

바로가기: **https://gyo6star8i.github.io/sign/install** (사본 만들기 화면으로 이동)

### 방법 2. 직접 설치
위 [설치 방법](#설치-방법-처음-한-번-약-10분)을 처음부터 따라 합니다.

### 받는 분께 알려 드릴 것
- 승인할 때 "Google에서 확인하지 않은 앱"이 나오면 **고급 → 이동 → 허용**. 개발자로 본인 계정이 표시되므로 안전합니다.
- 크롬에 구글 계정이 여러 개 로그인되어 있으면 "현재 파일을 열 수 없습니다"가 나올 수 있습니다. 시크릿 창이나 다른 브라우저로 여세요.
- 코드를 고친 뒤에는 **배포 관리 → ✏ → 버전: 새 버전 → 배포**(새 배포를 누르면 주소가 바뀜).

## 저장 위치

| 시트 탭 | 내용 |
|---|---|
| `Meetings` | 회의록 본문 |
| `Members` | 위원 명단, 비밀번호(암호화), 서명 이미지·일시 |
| `Log` | 로그인·서명·수정 기록 |
| `Pdfs` | 드라이브에 저장한 원본 PDF와 파일 확인값 |

시트는 설치한 사람만 볼 수 있습니다. 공유하지 마세요.

## 법적 효력과 원본 관리

「전자서명법」 제3조는 전자서명이 전자적 형태라는 이유만으로 효력을 부인할 수 없고, **당사자 간 약정으로 전자서명을 선택하면 서명·기명날인의 효력**을 가진다고 정합니다.
2020년 개정으로 공인인증서의 특별한 추정 효력이 없어졌기 때문에, 분쟁이 생기면 **누가·언제·어떤 내용에 서명했는지를 입증할 기록**이 중요합니다.
모두싸인 같은 전자계약 서비스도 같은 근거(전자서명법, 전자문서법)와 본인 확인·감사추적·위변조 확인으로 효력을 뒷받침합니다.

이 시스템이 갖춘 장치:

| 필요한 것 | 이 시스템 |
|---|---|
| 전자서명 사용 약정(동의) | 서명할 때 '내용 확인·동의'와 '전자서명 사용 동의'를 따로 받아 기록 |
| 본인 확인 | 위원별 개별 링크와 6자리 비밀번호, 5회 오류 시 잠금 |
| 감사추적 | 비밀번호 발급, 최초 열람, 서명 시각, 접속 기기, 마감까지 전체 이력을 PDF 2쪽 이후에 수록 |
| 서명 후 내용 변경 방지 | 서명 당시 문서 확인값(SHA-256) 기록. 모두 서명하면 자동 마감되고, 마감 후에는 수정이 잠김 |
| 원본 위변조 확인 | '구글 드라이브에 저장(원본)'으로 만든 PDF는 `?page=verify` 페이지에서 원본 여부 확인 |

**한계와 권장 사항**
- 휴대폰 본인인증이 없습니다. 관리자가 비밀번호를 본인에게 직접(개별 메신저 등) 전달해야 본인 확인의 의미가 있습니다.
- 접속 IP는 Apps Script 특성상 기록되지 않습니다(기기 정보만 기록).
- PDF 자체에 공인 전자서명(PKI)이 들어가지는 않습니다. 대신 드라이브 원본의 확인값으로 위변조를 검증합니다.
- 학교 공문서의 공식 원본은 **업무관리시스템(K-에듀파인)에 등록된 기록**입니다. 완성된 원본 PDF를 내부결재에 첨부해 등록하는 방식을 권장합니다.
  자필 서명 원본이 꼭 필요한지는 소속 교육청 지침을 확인하세요.

## 개발자용: 로컬 테스트
구글 서비스를 흉내 내는 테스트 서버로 화면과 흐름을 확인할 수 있습니다.

```bash
node dev/server.js
```

브라우저에서 `http://localhost:8787/exec?page=admin` 접속. 전체 흐름 자동 테스트(Playwright 필요):

```bash
node dev/e2e.js /tmp
```
